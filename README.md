# Omni DSG — сервер платформы студии

Этап 1: вход, роли и должности, проекты, файловое хранилище, журнал действий.
Node.js 22 без внешних пакетов, база — встроенный SQLite, файлы — на диске сервера.

## Запуск

```bash
cp .env.example .env        # при необходимости поправьте
npm start                   # http://localhost:3000
npm test                    # 9 сквозных проверок API
```

При первом запуске создаются шесть стандартных должностей и администратор. Если `ADMIN_PASSWORD` не задан, временный пароль выводится в лог — после входа система попросит его сменить.

Docker:

```bash
docker build -t omni-dsg .
docker run -d -p 3000:3000 -v omni-data:/data -e ADMIN_PASSWORD='…' -e COOKIE_SECURE=1 -e TRUST_PROXY=1 omni-dsg
```

Каталог `/data` (база `omni.db` и папка `files/`) должен лежать на постоянном диске — его и нужно бэкапить.

## Безопасность

- Пароли хранятся только как хеш **scrypt** с солью. Прочитать или выгрузить пароль нельзя — только сбросить: администратор получает временный пароль, сотрудник меняет его при первом входе.
- Политика пароля: от 8 символов, буквы и цифры.
- Сессия — случайный токен в cookie `HttpOnly; SameSite=Lax` (+ `Secure` при `COOKIE_SECURE=1`), в базе лежит только SHA-256 токена. Срок — 30 дней. Смена пароля, сброс, отключение или смена роли завершают сессии.
- Подбор пароля: 5 неудачных попыток на логин+IP за 15 минут, затем пауза. Время ответа не выдаёт, существует ли логин.
- Подделка запросов: каждый изменяющий запрос обязан прислать заголовок `X-Omni-Request: 1`.
- Файлы на диске лежат под случайными ключами, имя от пользователя не участвует в пути. Заказчик видит только файлы с меткой «заказчику».
- Нельзя отключить или понизить последнего администратора; менять администраторов может только администратор.
- Все значимые действия пишутся в журнал (кто, что, когда, IP).

## Права

Уровни входа: `admin`, `director`, `staff`, `client`. Администратор — всё. Директор — всё, кроме бота и команды. Заказчик — только свой объект и открытые ему файлы. Сотруднику права задаёт **должность**:

| Доступ | Что даёт |
|---|---|
| crm | заявки и клиенты |
| projAll | все проекты, а не только свои |
| stage | менять стадию и её готовность |
| tasks | ставить задачи |
| money | бюджет и оплаты |
| storage | хранилище: смотреть, загружать, удалять свои файлы |
| pub | открывать файлы заказчику |
| gantt | график |
| bot | настройки бота |
| team | сотрудники и должности |

Ещё у должности: стадии, в которых она участвует (0 Обмер … 5 Сдача), и доступ к Контуру — `none`, `view`, `notes`, `edit`.

## API

Все ответы — JSON. Ошибки: `{ "error": { "code", "message" } }` с понятным текстом на русском.
Изменяющие запросы: заголовок `X-Omni-Request: 1`.

| Метод | Адрес | Кто | Что |
|---|---|---|---|
| POST | /api/auth/login | все | `{login, password}` → cookie сессии |
| POST | /api/auth/logout | вошедший | выход |
| GET | /api/me | вошедший | профиль, права, стадии, доступ к Контуру |
| POST | /api/me/password | вошедший | `{current, next}` |
| GET | /api/meta | вошедший | справочники: права, стадии, роли |
| GET | /api/positions | не заказчик | должности и сколько на них людей |
| POST, PATCH, DELETE | /api/positions[/:id] | team | `{name, kontur, stages[], perms[]}`; удаление — если должность пуста |
| GET | /api/users | team | все пользователи |
| POST | /api/users | team | `{login, name, role, positionId, phone, password?}` → без пароля вернёт `tempPassword` |
| PATCH | /api/users/:id | team | `{name, role, positionId, phone, active}` |
| POST | /api/users/:id/reset-password | team | новый временный пароль, сессии сброшены |
| GET | /api/projects | вошедший | видимые проекты с командой |
| GET | /api/projects/:id | участник | проект |
| POST | /api/projects | admin, director | `{name, address, area, due, leadId, clientId, members[]}` |
| PATCH | /api/projects/:id | admin/director; stage — право stage | данные проекта, `stage`, `stagePct` |
| PUT | /api/projects/:id/members | admin, director, team | `{userIds[]}` |
| GET | /api/projects/:id/files | storage или заказчик | список (заказчику — только открытые) |
| POST | /api/projects/:id/files | storage | тело — сам файл; заголовок `X-File-Name` (URI-кодированный); `?public=1` при праве pub |
| GET | /api/files/:id/download | storage или заказчик | скачивание |
| PATCH | /api/files/:id | pub | `{public}` |
| DELETE | /api/files/:id | загрузивший, admin, director | удаление |
| GET | /api/audit?q= | admin | журнал действий |
| GET | /api/admin/export[?hashes=1] | admin | выгрузка базы в JSON; хеши паролей — только по флагу |
